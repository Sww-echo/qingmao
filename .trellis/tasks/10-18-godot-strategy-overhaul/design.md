# 玩法与技术设计草案

> 2026-10-18 · 历史产品方向。最新详细技术合同、玩法实验和顺序以 [架构计划](../10-18-godot-architecture-plan/README.md) 为准；P2–P4 待本版评审。

## 1. 方案选择

| 议题 | 推荐 | 理由与代价 |
| --- | --- | --- |
| 形态 | 大地图入口 + 2D 小场景 + 事件 + 回合战斗 | 强化空间体验，保留策略核心；需要场景制作 |
| 首轮范围 | 独立 14 日情境 | 42 次行动内检验取舍，不等于正式剧情压成十四日 |
| 平台 | 桌面优先、保留 Web | 用户已确认；首轮实测本机 macOS |
| 语言 | 类型化 GDScript | 便于编辑器与 Web 路径，TS 规则需要迁移 |
| 渲染 | Compatibility 作为首选基线 | 适合轻量 2D 与 Web；由最小导出确认 |
| 工程 | 仓库内 `godot/` 并行工程 | 保留当前 Web 可运行参考 |
| 参考规则 | 隔离 TS 测试情境 | 快速平衡并生成对照；迁移稳定后停止双实现扩张 |
| 存档 | 新格式、独立命名空间 | 新规则不能伪装兼容旧 v2；保留原版继续游玩 |
| 美术 | 可替换占位素材，统一 2D 风格 | 先验证玩法与可读性，再做正式资产 |

纯面板移植成本低，但空间体验提升有限。3D/即时战斗会引入地图、角色、动画和 AI 大量工作，当前没有证据支持同步扩大范围。

## 2. 策略模型

### 2.1 时间与空间

- 每日 3 行动；查看、界面管理、场景内普通走动不推进时间。
- 安全地点切换先保留免费规则，避免无意义走路成为成本。
- 出寨探索、办事、修炼等按行为扣行动，承诺前预览；同一探索中的走动不重复收费。
- 风险探索显示已知危险、补给和撤退规则，等待玩家选择时世界时间不偷跑。
- 独立情境建议从已开窍的一转方源开始，省去重复开场；资质不变，起始库存/资源由原型冻结。

### 2.2 经济与机会成本

| 行为 | 收益 | 成本/风险 | 策略用途 |
| --- | --- | --- | --- |
| 安全劳作 | 小额确定元石 | 行动、放弃机会 | 兜底和恢复 |
| 关系委托 | 元石、人情、担保 | 期限、交付、后续义务 | 经营路线 |
| 竹林探索 | 材料、情报、蛊的机会 | 真元、补给、伤害/暴露 | 高风险积累 |
| 温养修炼 | 有实际用途的能力门槛 | 行动、真元、资金周转 | 战备路线 |
| 处理痕迹 | 降低具体暴露 | 行动、钱或人情 | 降低未来威胁 |

原型可以 +2 元石劳作为初始参数。先计算 `净收入 = 行为收入 - 全部持有蛊的基础供养 - 额外消耗`，再定委托/探索收益。不能把兜底收入压成必死来制造策略。

无需给安全劳作机械递减，优先通过有限委托、限时机会与风险形成差异。低资源状态保留可行恢复入口；已明确承担致死风险或错过必要窗口不提供无条件复活。

### 2.3 成长与蛊虫

- 首轮只做一转内少量修为门槛，不扩张九转体系。门槛必须改变效率、真元承受或事件应对中的至少一项。
- 四蛊候选：月光（攻击）、玉皮（防护）、地听肉耳草（侦察）、酒虫（辅助/成长）；属于独立测试候选，不声称正式原著开局同期全部可得。
- 每蛊通过实际事件、委托或交易获得；发行版不提供调试加库存入口。
- 月光 + 防护适合正面应对；侦察 + 已落实关系可示警或寻安全安排；酒虫提高成长效率但有经济代价。
- 暂保留最多 4 个使用位，主要通过供养负担和场景需求限制全拿，避免只靠硬上限。
- 推荐已炼化持有蛊有基础供养，装备/催动另有成本；明确封存可降低维护并暂停能力。不能卸下后无限免费保留全部收益。
- 采用活跃、休眠、封存中的最少必要状态；首轮不做永久饿死与复杂食谱。收费、封存成本在原型阶段冻结。

### 2.4 关系与暴露

- 复用 `relations`，先让两位对象能提供实际任务、信息或担保，不给所有 NPC 做模拟。
- `suspicion` 表示会衰减的当下关注；少量暴露/承诺标记表示已目击、物证或欠下的约定。
- 优先使用有来源的标记，不堆叠多个含义相同的全局数值。
- 解锁依赖具体关系和承诺，不以“关系总和”包办政治。
- 提示被谁注意、原因、如何处理；处理需真实代价，不隐藏随机清零。

### 2.5 危机与战斗

独立情境建议采用小规模野外狼群险情，区别于正式第 165 日狼潮。

| 日期 | 机会/信息 | 检验 |
| --- | --- | --- |
| 1–3 | 基础收入、关系入口、蛊线索 | 理解行动与供养 |
| 4–7 | 巡山遇险、情报分歧、委托期限 | 投资产生不同选项 |
| 8–11 | 明确预警、战备或担保任务 | 无法把所有准备拿满 |
| 12–14 | 最终准备、危机应对、结算 | 准备兑现 |

两种应对至少可行：

1. 战备：修为、可用攻击/防护蛊和补给支持回合战斗，胜利仍产生损耗。
2. 侦察借势：情报 + 实际落实的人情安排换安全任务/庇护，承担资金与义务；不能只刷关系值无条件跳关。

钱能购买补给或履行约定，但不替代全部能力、情报与承诺。结算说明准备发挥了什么作用、缺什么、哪次选择留下了代价，不只输出总分。

保留敌人意图可见。攻击、防御、蛊、补给和撤退使用统一规则，界面只呈现结果。战斗出手不额外扣日程行动，进入探索/交战时结算日程成本。

### 2.6 事件预算与因果

至少 12 个独立事件：建议 3 个教学/情境、4 个经济/关系、3 个探索/情报、2 个危机。重复日常不计入数量。付费选项在承诺前显示条件，并提供符合情境的暂缓/离开处理。

依赖只表达真因果，多个机会可并行推进；错失高收益节点会增加难度，但不能无提示关闭全部路线。

## 3. 平衡验证

三类显式策略脚本：战备投资、情报关系投资、必要开场后只安全劳作囤钱。均使用公开合法动作与已知信息，不注入资源、不读取未来随机数。

- 开发集 100 个固定种子；另外 100 个独立保留种子，在规则冻结后评估。
- 暂定设计目标：两类投资策略保留集生还率各 ≥70%，纯劳作对照 ≤40%。这是待验证假设，不是已证明数据或用户已批准数字。
- 报告剩余元石、修为、可用蛊、受伤、暴露、行动分配与失败原因，避免只看胜率。
- 至少人工逐步审查两条成功、一条失败和一条同种子改变策略的因果对照。
- 不删除坏种子，不故意让对照脚本漏掉可见的必要生存动作，不只为两脚本硬编码解法。
- 若满足目标需要极端数值，先重审机制；区分脚本缺陷、经济问题、内容不可达和危机条件问题。
- 建议追加三名试玩者或三次结构化独立试玩，检验可理解性。无人可测时明确未完成，自动模拟不能代替体验评价。

## 4. 工程结构与权责

建议目录，本轮不创建产品工程：

```text
godot/
  project.godot
  domain/         # State、Action、Rules、Queries、RNG
  content/        # 已验证 JSON 与稳定 ID
  application/    # GameSession、内容加载、存档、界面投影
  scenes/         # title、world、location、event、combat、ending
  ui/             # 状态栏、预览、背包、通知
  assets/         # 图像/字体/声音与来源
  tests/          # 无界面规则与轨迹
shared/
  contracts/      # 内容/动作/存档格式
  fixtures/       # 跨引擎参考轨迹
src/game/prototype/ # 隔离 TS 情境
scripts/          # 导出、模拟、对照
```

只迁移首版规则，不复制所有旧篇分支，不引入 JS 虚拟机/嵌入网页作为长期规则桥接。

### 4.1 操作链

```text
玩家输入 -> GameSession.dispatch(action)
  -> Rules.validate -> Rules.apply
  -> 新状态 + DomainEvents / 拒绝原因
  -> 内存一次提交 -> 请求保存快照 + 信号/界面更新
  -> 保存完成反馈（失败保留内存进度）
```

界面、相机、声音、动画不写资源、旗标、RNG 或结局。非法操作无状态副作用、不抽 RNG、不记成功日志。存档失败保留内存进度，显示失败和重试，不冒充已保存。

Domain 无场景树依赖；GameSession 协调规则与持久化，不把每个系统变成全局 Autoload。先用主场景 + 会话节点、Control/Container UI、Node2D/Area2D 交互；没有寻路需求时不提前做复杂导航。

### 4.2 内容契约

- 保留稳定字符串 ID，中文显示名不作逻辑键。
- V1 以 TS content.ts 为唯一源，生成共享 JSON 并显式同步入 Godot；V1 对照通过后 V2 切换到新的唯一 JSON 编辑源，具体门槛见新计划 migration.md。不序列化可执行代码。
- `shared/` 位于 Godot 资源根之外，需通过明确脚本生成/复制到 `godot/content/` 和测试资源目录；不能依赖导出后不存在的 `res://../`。指定唯一权威源、生成标记与漂移检查，避免手改两份内容。
- 需求与效果使用有限的 `requirements/effects` 类型；复杂行为由双方已实现的 effect 类型承担，不能执行内容中的任意脚本。
- 日期、资源、计数、RNG 均为有界整数，JSON 导入显式校验转换，不能依赖自动推断。
- 分开 `formatVersion`、`rulesVersion`、`contentVersion`；校验重复 ID、缺引用、奖励、不可达节点与依赖环。
- 季节、可选事件、有效能力、剩余时间由权威状态推导，不存易冲突的重复字段。

### 4.3 规则一致性

- 比较新情境同一规则版本的 TS 与 GDScript，不要求新策略复现旧狼潮算分。
- 固定初态、种子、内容版本与动作；每步比较资源、日期、修为、关系、旗标、供养、战斗、结局和 RNG。
- V1 对照整个既有 State，包括确定日志、账本与行动计数；只排除新应用 envelope 和 UI 状态。对象键排序、数组保留顺序，禁止未定义投影就删字段。
- JS RNG 使用 `Math.imul`、uint32 截断与逻辑右移；GDScript 64 位整数不能机械照抄。先做黄金向量，再测完整动作轨迹及抽样次数。
- 调试夹具入口不能进入正式发行操作流。

## 5. 存档与兼容

- 新试玩独立命名空间，例如 `user://qingmao_strategy_demo/`，P2 冻结最终名称。
- 包含格式、规则、内容版本、情境 ID、完整已校验状态及必要跨局数据。
- 当前档 + 上一成功备份：先临时写并校验，再按平台能力替换。必须故障演练，不能将桌面原子替换假设直接套到 Web。
- 合法操作后保存事件、战斗、RNG、供养和世界状态；加载按识别/校验/决定恢复或拒绝/一次替换内存顺序执行。
- 旧 v2 档提示不支持此情境，保留文件，不静默重开或覆盖；旧 Web 工程仍能继续原档。
- Web 持久化依赖浏览器站点存储；保留导入导出，不假定隐私模式、清数据、换地址后仍有档。
- 若用户要求旧档迁移，新增专门子任务定义映射、缺省值、失败恢复与单向/双向边界，重新估算。

## 6. 平台与表现

- 查询日官方证据见 `research/godot-migration-evidence.md`；其中版本属于研究候选，W0 核验实际可取得的稳定 Godot 4 并锁定精确版本/摘要及同版模板，不预设候选已可运行。
- Web 采用 GDScript、Compatibility/WebGL2 的可行路径，早做最小导出。单线程为首轮候选，线程/共享内存与部署头只有确需时再引入。
- 当前 PATH 和常见应用目录未发现 Godot；没有运行/导出验证，安装和环境准备属于 P2 的实际工作。
- P2 一并明确 `.godot/` 导入缓存、临时导出与 `artifacts/` 的忽略和保留策略，正式资源与生成物分开。
- 首轮实测 macOS 本地试玩。Windows、签名公证、商店上架不作未经验证承诺。
- 建议覆盖 1280×720 与 1920×1080，支持键鼠焦点、长文滚动、窗口缩放。手机/手柄不列首版门槛。
- 现有 SVG 是候选素材，React JSX 不能直接导入；检验字体、渐变、遮罩与滤镜。Godot 默认 SVG 纹理导入与 DPITexture 的行为不同，不承诺任意 SVG 功能。
- 中文字体本地打包并记录授权；资产预算与性能基准待最小场景实测冻结。
- 雨雾/月光等表现服从可读性、性能与可替换性，不能承载规则状态。

## 7. 风险、退出点与扩展

| 风险 | 提前验证 | 回退 |
| --- | --- | --- |
| 纯劳作仍包办所有条件 | P1 模拟与轨迹 | 留在 P1，先不做全场景 |
| 双语言漂移 | RNG/逐步对照 | 缩小 effect 范围，先修契约 |
| 14 日不能外推 165 日 | 下一轮中期情境 | 不按比例放大收益/日期 |
| 美术吞预算 | 占位素材先完整闭环 | 延后正式资产 |
| 旧档预期不同 | 实现前确认独立档 | 增迁移子任务并重估 |
| Web 差异 | 最小工程早导出 | 记录可复现阻断与修复成本 |
| 历史文档误导 | 代码审计与版本核对 | 实施阶段更新当前说明，保留历史边界 |

首版通过后依次规划中期经济、商队/考核实际玩法、正式狼潮，再考虑合炼和更长篇内容。当前不承诺完整青茅山的交付日期。

回退按本任务文件范围执行，不整仓库 reset，不修改或混入用户已暂存的原著资料。
