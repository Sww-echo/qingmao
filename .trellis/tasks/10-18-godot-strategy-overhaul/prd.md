# 青茅山 Godot 4 改造与生存策略升级

> 2026-10-18 · P1 已获授权并实现；最新要求先评审详细 Godot 架构计划，P2–P4 未开工。

## 1. 目标与玩家价值

逐步改造成 Godot 4 的 2D 场景探索与生存策略游戏。玩家围绕有限行动、真元、元石、蛊虫和人情制定不同计划，能从结果中理解成败原因。

推荐先交付小范围完整试玩，检验策略与迁移方式，通过后再规划正式 165 日内容扩展，避免同时承担引擎重写、美术制作和长篇内容扩充。

## 4. 已确认首版范围

### R1：独立短周期试玩

- 14 个行动日、每日 3 次行动，目标单局 20–35 分钟。
- 固定方源与丙等四成四设定；这是独立测试情境，不声称复刻原著十四日，不改写正式 165 日时间线。
- 学堂、客栈、竹林三个地点，至少 12 个独立事件、4 种功能明确的蛊、1 类可实际交战的敌人、1 次阶段危机。
- 场景内走动和查看信息不耗行动；有收益或推进世界的办事行为明确标注耗时。

### R2：经济、成长与机会成本

- 安全劳作兜底；委托、探索、关系收益具有不同门槛、成本与风险，不能只换名称。
- 修为改变至少一项真实能力或危机应对条件。
- 至少两类可行策略：战备投入与情报/关系投入；允许混合，不用职业锁死路线。
- 不靠重复次数惩罚强制轮换按钮，优先用任务容量、需求、资金周转与风险解释收益。

### R3：关系、疑心与信息

- 至少两个关系对象有任务、担保、庇护或情报用途。
- 普通关注可以衰减；已留下的暴露线索需付出代价处理，不能睡觉清除全部后果。
- 高风险选择在承诺前显示确定成本、已知危险与未知信息；不捏造精确概率。
- 引导提供目标、机会和风险，不持续替玩家给出唯一最优操作。

### R4：蛊虫与回合战斗

- 攻击、防护、侦察、辅助四种用途均可实际使用，获得方式、供养和使用条件可查。
- 供养义务不能靠当日卸下或危机前换装规避；休眠蛊不贡献有效能力。
- 战斗呈现敌人意图、真元、受伤与撤退代价；撤退不领取胜利奖励。
- 首版不要求完整合炼树，后续单独评审。

### R5：阶段危机与可解释结果

- 危机有预兆、筹备、应对和结算，不在最后一天突然按隐藏总分判生死。
- 至少两种准备能通过危机；纯囤钱不能包办全部条件，但储备仍有价值。
- 结算说明应对方式、发挥作用的准备、损失和不足条件。
- 死亡、错失必要窗口、承担明确风险均可真实失败，并记录原因。

### R6：Godot 体验与存档

- 桌面新局、地点交互、事件、战斗、日结、存读档、结算形成完整闭环。
- 首轮在本机 macOS 实测；Windows 属后续发行目标，未经实机验证不宣称已支持。
- 保留 Web 导出路径，交付冒烟验证或可复现的阻断报告。
- 推荐新试玩独立存档，不自动覆盖/转换旧档；旧 Web 版继续读取原档。
- 重开后继续同一日、待决事件或战斗；非法/损坏存档不能部分加载。

## 5. 验收标准

| ID | 可观察结果 | 验证方式 | 映射 |
| --- | --- | --- | --- |
| AC1 | 桌面包经三地点真实操作从新局走到结算 | 实机完整流程 | R1、R6 |
| AC2 | 两类策略各有成功轨迹，关键投入和危机应对不同 | 固定种子与合法动作记录 | R2、R3、R5 |
| AC3 | 劳作、委托、探索结果不同，改变投入会改变可用选项 | 对照轨迹 | R2 |
| AC4 | 修炼、有效蛊、关系各至少改变一次真实结果 | 因果对照用例 | R2–R4 |
| AC5 | 供养、休眠、装备、撤退、错失窗口不能被 UI 或导入绕过 | 边界与非法输入测试 | R3–R6 |
| AC6 | 同规则版本 TS/Godot 对约定轨迹产生相同规则状态 | 跨引擎逐步对照 | R6 |
| AC7 | 事件中/战斗中/日结后恢复一致；坏档回退或明确报错 | 存档故障演练 | R6 |
| AC8 | 原 Web 构建和旧规则回归保留，新旧档隔离 | 回归与格式隔离用例 | R1、R6 |
| AC9 | 有多种子策略报告和纯劳作对照，不只两条手挑路线 | 开发集与保留集分别报告 | R2、R5 |
| AC10 | Web 结果记录浏览器、渲染、加载、输入和持久化 | 冒烟或阻断报告 | R6 |

平衡数字是设计假设，见 `design.md`。证据反驳目标时应回到规划，不能删失败种子凑验收。

## 6. 首版不包含

- 3D 大世界、即时动作战斗、联网、账号、服务器和云存档。
- 完整 165 日内容、整篇青茅山、血湖/神捕/白凝冰等远期系统。
- 完整政治/市场模拟、全部蛊和合炼树、旧原创篇内容迁移。
- 旧档双向自动转换、正式全量美术、商店上架、签名公证、外部公开发布。
- 保证沿用现有单文件 `play.html` 分发形式。
