# 青茅山沙盒改造：时间压力与生存结局

## Goal

把方源篇从「按顺序走完十四段剧情的线性章」改成「有世界时钟的生存沙盒」的第一阶段：引入季节与固定世界事件、主线窗口与错失、狼潮硬截止与多层结局。同时把整体游戏大纲作为长期设计依据落到仓库中。

## Background

现有实现（`docs/FANG_YUAN_PLAN.md`、`src/game/fang-content.ts`）是一条强前置依赖的线性流程：每节点必须完成，只有两个固定选项，只有一个成功终点 `fy-first-gu`；方源篇日数上限为 10000（等于无时间压力）；`FANG_ENEMIES` 为空。这与「让玩家以方源身份选择，看能不能像他那样活下来」的目标不符。

本任务只做第一阶段：**时间会推进、窗口会关闭、狼潮会结算、游戏不再在报验后结束**。经济、政治、战斗接入、商队内容、石林、血湖、再次重生留给后续阶段。

## Requirements

1. 新增世界时钟：由 `day` 派生季节（每季 30 日）与年份；固定世界事件表（开窍大典、商队、年末考核、狼潮前兆、狼潮）。
2. 开窍大典限第 2–5 日；逾期未开窍按死局 `fy-missed-awakening` 结算。
3. 狼潮为硬截止（第 165 日结束当日结算），按境界、蛊虫、元石、疑心、关键旗标打分，分死亡 / 存活 / 立足三档。
4. 主线机遇改为开放事件图：`after` 只记真实因果，删除顺序依赖；带 `closes` 的机遇逾期写 `missed-<eventId>` 并永久关闭。
5. 地点按时间与真因果开放（市集第 3 日、竹林第 6 日；溪边、石洞仍需找到酒虫踪迹）。
6. 报验从「章节结局」降级为里程碑 `milestone-first-gu`，报验后游戏继续。
7. 结局体系：`fy-wolf-tide-stood` / `fy-wolf-tide-survived` 计入成就；`fy-wolf-tide-death` / `fy-missed-awakening` 仅作结算展示。
8. 存档升级到 v2：新增 `worldEvents`，校验世界事件顺序与开放日、里程碑一致性；**不兼容 v1 方源档**。
9. UI 呈现时间压力：日程条显示季节与距狼潮天数，侧栏显示下一世界事件与错失，结束当日对话框预告次日事件，结算页说明死因与错失。

## Constraints

- 原创「石灯遗藏」支线保持原行为不变。
- 日期与耗资为游戏化压缩，不声称是原著逐日账目。
- 所有状态变更仍走纯函数引擎，UI 不直接改状态或写结局。

## Acceptance Criteria

- [ ] `npx tsc --noEmit` 通过；`npm run build` 通过。
- [ ] `npx vitest run` 全部通过（含新增的世界时钟、窗口错失、狼潮评分与结算测试）。
- [ ] 新局第 1 日：`worldEvents` 为空、`rank 0`、`activeEvent: 'fy-rebirth'`。
- [ ] 第 5 日后仍未开窍 → `fy-missed-awakening`（defeat），且无法继续。
- [ ] 第 165 日结束当日按真实本钱结算，且结算后拒绝继续行动。
- [ ] 主线机遇可并行（客栈/买酒不依赖家宅/雨中试炼）；逾期机遇写 `missed-*` 且不可再进。
- [ ] 报验后 `ending` 为 null 且含 `milestone-first-gu`，可继续修炼与推进日期。
- [ ] 存档往返保持 `worldEvents`、里程碑与结局一致；篡改世界事件顺序/开放日/结局错配被拒绝。
- [ ] 原创支线相关测试与行为不变。
