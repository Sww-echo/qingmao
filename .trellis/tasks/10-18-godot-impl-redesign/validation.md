## 1. 与已有验证的关系

- 沿用父计划规则：不写装饰性镜像测试；原生输入/渲染交给真实窗口；报告记录时间、源码标识、引擎版本串、OS、渲染器、scenario/rules/content/hash、命令、退出码、种子集、结果与**未测项**；大体积产物放被忽略的 `artifacts/godot/`。
- P1 的 295 项测试与 600 局数据只覆盖 TS 侧，**不得转述为 Godot 通过**；旧 Playwright 首条失败的基线保留（改相关 UI 时再核对，不删测试）。
- W0 证据（`../10-18-godot-domain-foundation/w0-toolchain-evidence.md`）的未验证项继续有效，直到被后续工作包覆盖。

## 4. 证据与报告规则

- 门槛报告字段（沿用父 §5 并补充）：时间；源码标识/dirty；`GODOT_BIN --version` 与 4.7.2-stable 串；OS/CPU/渲染器；pack id / scenarioId / rulesVersion / contentVersion / contentSha256；执行命令与退出码；种子集清单；结果；未测项。
- **首差报告**（V4/V5）：run id、步号、动作 JSON、期望与实测哈希、期望文件路径；不得吞掉不一致；修复后重跑该集合全量。
- **留出集纪律**：冻结规则/内容哈希 → 登记 → 首跑 → 无论结果进报告；若需修正，旧留出集作废并启用 30001–30100。
- 未测项必须显式列（沿用 W0 证据的姿态）；"headless 通过"不能替代真实窗口操作。
- 负向断言格式：`{code, fieldPath}` + 副作用为零的断言（revision/RNG/日志/账本全等）。

- **现有入口**（P1 侧，保持可复跑）：`npm run check`、`npm run test:e2e`（旧基线）、`npm run prototype:freeze -- --check`、`npm run content:validate`、`npm run prototype:replay`、`npm run prototype:audit-combat`、`npm run prototype:simulate ...`。
