## 2. 设计原则

1. **每天有决策**：以每天有不止一种值得考虑的投入为设计目标；静态窗口覆盖不等于某条路线仍有可执行事件，分别检查窗口、实际可选项与选择后果（§10）。
2. **专精有回报、全能不可行**：三路线（战备/借势/劳作）在 42 个行动里各自花得起，但花不起两条半。
3. **风险可读、代价可算**：疑心、暴露、缺口、盘问都在 UI 可查；没有隐藏数字。
4. **失败可解释**：结局必须列清"哪些准备起了作用、哪些没兑现"。
5. **数值服务于节奏**：一切调参以第 10 节指标为准，先保节奏再求精确。

## 3. 日循环与行动经济

每个白天：**3 个行动**，然后 `END_DAY` 结算。行动全集沿用 V1（精确类型与拒绝语义见 contracts.md §2）：TRAVEL 移动（免费）/ WORK 劳作 / TRAIN 演武修行 / SCOUT 竹林侦查（无地听草也可冒险，有效地听草提升收益并免除风险）/ REST 歇息调息 / BUY 采买 / OPEN_EVENT·CHOOSE·DISMISS_EVENT 处理事件 / EQUIP 装备 / GU_MODE 封印与唤醒 / CLEAR_EXPOSURE 销案 / COMBAT 战斗走子 / END_DAY 结束一天。不是每种动作都扣日行动：移动、采买、装备、打开/收起事件免费，提交事件选择才按 actionCost 扣费。

END_DAY 顺序（V1 源码为基线，v2 只插入 D1 的明确分支）：
1. 蛊的当日义务结算（未封印的蛊各扣 1 元石；不可用封印规避同日义务）；
2. **第 14 日独立分支**：D1 将已触发但未了结的盘问转为一条暴露，然后打开强制危机并返回；不推进日期、不恢复生命/真元、不衰减疑心、不重置行动。这与 V1 的最终日边界一致；
3. 第 1–13 日推进到次日，关闭已过窗口 → `missedEvents`，重置 3 行动并做 V1 夜间恢复；
4. **（v2 新增 D1）** 用衰减前疑心判断阈值 ≥4，尚未触发过则挂起 `inquiry-due`；盘问只在第 8–14 日窗口内出现，早触发只挂起；
5. 疑心每日 −1 衰减，重置当日义务标记。未兑现承诺在结局根据状态解释，不在 V1 状态中凭空新增 reason 字段。

## 5. 系统设计

### 5.1 经济

沿用 V1：劳作 +2 石/行动；药草 2 石、酒 3 石；蛊价与维持（玉皮 8、地听草 8、酒虫 6；未封印蛊 1 石/只/日）；暴露了结 4 石。
V2 新增收支（**假设值，W6 校准**）：

| 项 | 时机 | 数额 | 设计意图 |
| --- | --- | --- | --- |
| 夜巡加急 | 8–11 日，1 行动，队长 ≥2 | +4 石，**疑心 +2** | 快钱与低调查的取舍；单次 |
| 加固栈院 | 10–13 日，1 行动 | −8 石 | 后段资金去向；危机战前两回合受伤 −2 |
| 年市·药材 | 11–13 日 | −5 石 → +3 药草 | 批量折价（省 1 石），清仓感 |
| 年市·封坛 | 11–13 日 | −7 石 → +3 酒 | 批量折价（省 2 石） |
| 押运年货 | 11–13 日，掌柜 ≥3 | −1 药草 → +7 石，掌柜 +2 | 末段安全差事，换出药草预算 |
| 盘问·打点 | 触发后 | −6 石 | 疑心的钱解法 |
| 庇护缺口补齐 | 危机结算时 | −4 石/点，最多补 2 点 | **钱不能代替准备，但能救"差一点"**；这是唯一让库存在后段产生意义的出口 |

设计约束：任何单靠资金的路线都不足以完局（纯劳作 + 买齐三蛊在 V1 已证明失败；缺口补钱封顶 2 点同样不足）。

### 5.2 成长与门槛

- 修行/打坐数值沿用 V1（修为上限 60；每 12 修为 +2 真元上限）。
- **演武试招**（新增）：学堂，7–11 日，1 行动 + 3 真元，要求**修为 ≥18**。得到旗标 `drilled`：危机战开场获得一次免费攻击（优先月刃，若不可用则普攻，真元照常）。这是修为从"隐含伤害阈值"变成"明确机会门槛"的关键改动。
- **复核退路**（新增）：竹林，9–13 日，1 行动，要求**情报 ≥6 且地听草可用**。得到旗标 `safe-route`：危机庇护需求 −1（等同于准备值 +1），队长 +1。让情报/地听草专精在终局兑现。
- 战备路线在 V1 就会把修为练到阈值以上，因此 `drilled` 对两条成功路线都开；劳作路线修为不足天然拿不到（与"劳作必败"一致）。

### 5.3 关系

沿用 V1 两条链（队长：差事 → 帮闲 → 值夜…；掌柜：引荐 → 账目 → 囤货…），数值不改。V2 增加**末段二选一**：

- **随队巡山**（学堂，11–13，1 行动，队长 ≥3）：触发与巡逻同规格的战斗（可撤退，无胜利奖励以外的一切照旧）。胜利按 V1 巡逻规则结算（元石 + 队长好感 + `patrol-cleared`）。
- **押运年货**（客栈，11–13，1 行动，掌柜 ≥3，−1 药草）：+7 石，掌柜 +2。
- 二者**互斥**（用 `flag present:false` 表达）：11 日之后只能兑现一方的信任。这是关系线在终局的第一次真实代价，而非纯加法。

### 5.4 风险：疑心盘问（新规则 D1）

- 疑心来源：竹林越界 +3、无有效地听草的 SCOUT +3（均沿用 V1）、**夜巡加急 +2**；第 1–13 日跨日时衰减 −1。
- **阈值 4**：第 1–13 日夜间衰减前疑心 ≥4 且从未触发过 → 挂起**学堂盘问**（8–14 日有效，不占行动，打开后仍可暂缓）：
  - 「使钱打点」−6 石，疑心 −6，了结；
  - 「托人情」队长 −2，疑心 −6，了结。
- **未了结后果**：第 14 日 END_DAY 供养后、危机打开前，挂起但未完成的盘问生成唯一持久暴露 `inquiry-unresolved`。按既有暴露公式使庇护准备值 −1、危机每次敌方基础伤害 +2，并进入结局 reason；不会因疑心自然降到 0 而免责，也不按疑心点数反复叠加。已了结或从未触发则没有该痕迹；完整合同与测试见 contracts.md D1。
- 触发取决于时序，不是拿过两项收益就必定触发：例如第 7 日越界 +3，跨日降到 2，第 8 日夜巡 +2，晚间达到 4；若越界更早，疑心可能已衰减，不会触发。无蛊连续侦查是另一条触发路径。**阈值/数值是假设，W6 需同时验证触发与不触发轨迹。**

### 5.5 蛊与蛊的维持

完全沿用 V1：四蛊（月刃/玉皮/地听草/酒虫）配发或购得；清醒/休眠/封印状态；未封印每天 1 石；购买当日/配发当日的义务不能靠封印规避；装备与否不影响义务。V2 不改。

## 6. 战斗 v2

保留：意图可见、伤害含暴露修正（沿用 V1 公式）、撤退语义（普通战与危机战的差异沿用 V1）、药草/酒消耗上限（以 V1 content 参数为准）。
改动（**规则增量 D3–D5**）：

1. **危机战双阶段**（D3）：`狼群前锋`（HP 假设 30–34，意图循环 6/10/4）→ 击倒后**喘息**（真元 +3，上限封顶；护体清零）→ `头狼`（HP 假设 34–40，意图 8/12/5）。两阶段是**同一场战斗**：药草/酒总量共用、回合数连续。总血量 64–74，落在 V1 危机战 60–76 的区间内，避免整体难度漂移。数据表达：敌人定义新增可选字段 `next: EnemyId`（见 contracts.md），引擎在击倒后加载下一阶段而不是判胜。
2. **演武先手**（D4）：危机战开场，若 `drilled`，自动执行一次免费攻击（见 §5.2），日志单独成条。
3. **加固减伤**（D5）：仅阶段一的前两个回合，受到伤害 −2；沿用 0 基回合计数，即 `turn=0/1` 生效，`turn=2` 起不生效，阶段二不继承。
4. 普通战斗（救商旅、随队巡山）完全同 V1，单敌人、单阶段。

## 7. 危机 v2（第 14 日黄昏）

### 7.1 两条路线（选择不变）

- **迎战**：直接进入双阶段危机战。
- **借势**：要求沿用 V1（地听草可用、情报 ≥5、队长 ≥3、掌柜 ≥4、`route-chart`、值夜兑现、囤货兑现），花 6 石；结算见下。

### 7.2 结算公式（D2）

```
需求 demand = RNG 抽样 8–12（危机结算时抽样，不可提前窥见） − (safe-route ? 1 : 0)
准备 readiness = 情报 + 队长 − 暴露数        （沿用 V1 公式，含 D1 未了结盘问的 1 条暴露）
若 readiness ≥ demand → 成功（躲过狼潮）
否则 gap = demand − readiness
    若 gap ≤ 2 且 元石 ≥ 4×gap → 付钱补齐，成功（账本记录"破财"）
    否则 → 被截住：生命 −10，随后强制进入危机战（可存活，视剩余状态）
```

### 7.3 数值与难度取向

- 沿用 V1 的 8–12 抽样与准备公式；V2 的修正是 `safe-route −1` 与缺口补钱。目标：借势路线在完成全部四件套+复核退路后**稳赢**（准备值 ≥ 需求上界），未完成者有机会被救但因补钱上限 2 点而不可靠。
- 劳作政策沿用 V1 的合法准备（包括共同开局领取月光蛊），但不投资修为/关系/庇护链，因不满足借势前置只能迎战，不是先无条件借势再被截住。W6 须复核 V2 下的失败率，不能用 V1 失败直接证明改版后必败；若失败目标不成立则回到规划/校准，不删失败或意外成功种子。

### 7.4 结局

结局 = 存活/死亡 + **reason 清单**。V2 扩展 reason 来源：未兑现承诺、错过窗口清单、盘问未了结、演武未打、复核退路未做、缺口补钱、暴露次数、每只蛊的终局状态。要求：任何一个死亡结局都能从清单直接读出"如果重来该改哪两件事"。

## 10. 平衡目标与实验方法（W6 执行，W8 复核）

**种子集**：开发集 1–100（调参用）；回归集 10001–10100（V1 旧留出集，已被看过，只做回归）；**新留出集 20001–20100**（调参前登记，冻结后首跑，只跑一次；若需修正则作废并启用 30001–30100）。

**门槛（开发集，三条策略各跑一遍）**：

| 指标 | 门槛 | 说明 |
| --- | --- | --- |
| 战备路线存活率 | ≥70% | 沿用父任务阈值 |
| 借势路线存活率 | ≥70% | 沿用父任务阈值 |
| 劳作路线存活率 | ≤40% | 沿用父任务阈值 |
| 后段非劳作密度 | 战备/借势两路线在第 8–14 日（21 个日行动）中，实际消耗的非 WORK 日行动 ≥9 次 | 每条开发集轨迹分别断言；只计扣费行动，免费移动/开关事件/采买/战斗走子不计，不能靠重复免费动作凑数 |
| 机会窗口覆盖 | 内容表第 5–13 日每天至少 1 个可选事件窗口（含复用）；第 7–13 日每天至少 1 个新增事件窗口 | 静态检查时间窗并输出按日 ID；不把“窗口内”误当“该玩家尚未完成且满足条件” |

**报告指标（不作门槛，只记录）**：完局平均剩余元石（期望从 V1 的 27–32 降至 5–15）、盘问触发率、演武完成率、缺口补钱使用率、双阶段战平均回合数、每策略的 reason 分布。另附每策略第 5–13 日的实际可选事件/未满足条件/已完成或互斥原因矩阵；已做完可选内容不判静态覆盖失败，但若后段仍只剩劳作，必须记录为玩法风险。

**留出集纪律**：冻结规则/内容哈希 → 登记 → 首跑 → 无论结果如何都进报告；若失败，修正后旧留出集作废，新开 30001–30100。
