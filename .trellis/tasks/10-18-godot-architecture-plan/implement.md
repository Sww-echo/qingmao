# 工作包、里程碑与实施顺序

2026-10-18 · 全部为后续计划。本轮不打勾产品实现项；P1 既有证据另见原任务。该规划子任务负责方案，产品实施仍由 P2/P3/P4 分别承接。

## 1. 依赖与评审门槛

```text
本版架构/玩法方案评审
    ↓
P2: W0 原生可见壳 → W1 数据合同 → W2 V1 规则对照 → W3 会话/存档
    ↓
P3: W4 可玩第1日 → W5 三地点完整V1 → W6 有限V2实验 → W7 体验收敛
    ↓
P4: W8 候选冻结、独立评估、桌面包、Web结果
```

W0 只做可见工程和展示，不在不完整规则上拼一个假通关。每包都有演示或执行证据；“运行看看”时优先启动最近可运行的 Godot 产物，并说明它的范围，不能再以旧 Vite 页面当新成果。

## 2. W0：工具链与第一个可见窗口（P2，1–2 人日）

前置：本版方案已评审；P1 冻结文件可读。先核验实际可取得的稳定 Godot 4 版本，不沿用未经运行确认的 4.7.2 候选结论。

- [ ] 记录二进制来源、精确版本、SHA256、CPU/OS、同版模板与渲染设置；不改系统默认配置掩盖问题。
- [ ] 新建并行 `godot/`，Compatibility、GDScript、720p 基准和缩放；定义缓存/生成物/导出物的跟踪策略。
- [ ] 主场景、标题、中文本地字体、学堂占位场景、可移动角色、一个能打开说明的交互目标。
- [ ] 跑编辑器导入与原生窗口；验证字体、窗口缩放和键鼠焦点。
- [ ] 做最小 macOS 导出并从产物启动；试最小 Web 导出/浏览器加载，记录阻断，不延至最终阶段才发现。

输出：工具链说明、原生运行命令、最小导出和截图/观察记录。窗口标明“架构演示：未接入完整规则”。

退出：真实 Godot 窗口能打开、文字可读、角色能移动、目标能交互；桌面启动通过，Web 有实际结果。回退：仅保留最小可导入工程，修导入/字体/渲染，不开始全量场景。

## 3. W1：内容、模型与生成合同（P2，1–2 人日）

- [ ] 按 [contracts.md](contracts.md) 定义 State/Action/Catalog、错误码与序列化边界；完整映射 types.ts。
- [ ] 做严格内容与状态验证，建立固定危机节点、引用、可选分支、整数/上限负例。
- [ ] 新增 `godot:sync-content` 及 `--check` 入口（计划名），复制 V1 已冻结数据/测试夹具到资源根，生成来源标记/摘要。
- [ ] 校验导出资源过滤，确保实际包能读 JSON/字体；测试夹具与 debug 入口从正式导出排除。
- [ ] 明确追踪 `project.godot`、`.tscn/.gd`、必要 UID/导入配置/许可文件；忽略 `.godot/` 缓存、模板下载和临时导出。具体随锁定版本确认。

退出：源改动/副本漂移/缺资源均能明确失败；Godot 启动读取同一版本 Catalog。回退：源仍是冻结 TS，不在两边手动补数据。

## 4. W2：纯规则等价迁移（P2，3–4 人日）

- [ ] 先移植 Rng32：四组黄金向量、边界 uint32、连续抽样和 draw count。
- [ ] 迁移 create/requirements/queries；查询与无效动作不抽 RNG、不改输入。
- [ ] 迁移资源、成长、关系、蛊/供养和 effects；再迁移事件/日结，最后战斗/危机。
- [ ] 用 SceneTree runner 提供失败非零退出、首差 step/action/JSON path；不为纯规则引入场景。
- [ ] 三份 seed42 逐步全状态对照，再跑开发/既有保留集 600 局；保留失败轨迹。
- [ ] 语义差异返回合同/实现修复，V1 不为“迁移方便”改费用或删日志。

输出：GDScript 规则、测试 runner、可重现比较报告。演示可附规则结果面板，但标注尚非完整试玩。

退出：初态/每步/终态/摘要、日志/账本/RNG 一致，拒绝无副作用。回退：停在最后通过的规则组，不接一套 UI 临时规则。

## 5. W3：会话、保存和恢复（P2，2–3 人日）

- [ ] GameSession 安装状态、revision、runId、命令去重/过期拒绝、结果事件与 ViewModel。
- [ ] SaveEnvelope/Codec、单写入队列、当前/备份、导入导出；存档错误不回滚已提交内存。
- [ ] 在待决事件、巡逻战、最终战、日结后、结局保存/退出/恢复。
- [ ] 注入磁盘失败、损坏、版本错误、过期保存完成、退出中断；确认有效档未被破坏。
- [ ] Web 实测保存/同步能力，冻结可保证的反馈语义；桌面与 Web 不共享原子写假设。
- [ ] 冻结给 P3 的最小 API；将已验证模式写入适用 Godot spec，避免把本计划整份复制成已验证规范。

退出：P2-A–E 有证据；会话单一状态、恢复无额外收益、未保存反馈准确。回退：暂停表现接入，保留内存/原档/可导出快照。

## 6. W4：能亲手玩的第 1 日（P3，2–3 人日）

- [ ] 标题新局/继续/导入、HUD、学堂场景接实际会话；去掉 W0 占位数字。
- [ ] 至少一个事件、WORK、TRAIN、END_DAY 全走真实规则；显示成本/拒绝原因、供养和日结。
- [ ] 管理页和模态只查询投影，鼠标/键盘焦点互斥；双击不能多扣。
- [ ] 新局→一日操作→保存→关闭窗口→继续，真实输入完成；记录命令序列与恢复状态。

输出：可试玩的第 1 日。演示必须讲清“已接真实规则，但其余场景仍未齐”。退出：HUD 和重开后的状态一致，无调试注入。回退：只简化面板/美术，不用假数字冒充进度。

## 7. W5：三地点完整 V1（P3，3–4 人日）

- [ ] 三地点场景和交互目标，移动/预览免费，跨地点由 TRAVEL 成功后切场景。
- [ ] 全部 19 事件接入、两关系对象、四蛊、补给/封存/唤醒/痕迹处理。
- [ ] 回合战斗、意图/伤害预览、补给本场次数、撤退、危机选择、结局。
- [ ] 两条成功 + 一条失败用真实输入完成；不从 fixture 直接灌终态充当试玩。
- [ ] 检查危机到达/日结回顾顺序、普通事件暂缓、零行动和低资源恢复、重载场景不发奖励。

退出：完整 V1 可以从头玩到结局，已实现合同不漂移。此时评审“移植是否完成”；尚不能称玩法节奏优化完成。回退：保留 W4 可运行场景并修接线。

## 8. W6：V2 玩法改造实验（P3，2–4 人日）

- [ ] 完成 [migration.md](migration.md) 的内容权威切换记录，V1 基准不改；V2 独立版本/存档。
- [ ] 按 [gameplay.md](gameplay.md) G2 重排/改写 3–4 个现有事件，不并行增加全新大系统。
- [ ] 暴露后期机会、准备条件和实际成长用途；保持可选风险/安全恢复。
- [ ] Godot 下运行公开信息政策/混合策略、记录日程分配、工作占比、失败原因及同种子分支结果。
- [ ] 只用开发集调参；V2 新盲测集合调参前登记，W8 冻结后首次执行。
- [ ] 对照实验若只有胜率下降、没有新增有因果的选择，回退该改动并记录原因。

退出：两路线可达、后段至少两次有因果取舍、重复度前后报告；新增状态/effect 均有保存/边界测试。此门槛是可继续试玩的候选，真人可理解性仍待 W7/W8。超出本包内容预算则拆新任务重新估算，不把扩范围藏进实验。

## 9. W7：交互和可读性收敛（P3，1–2 人日）

- [ ] 1280×720/1920×1080、窗口缩放、中文长文/滚动、键盘完整闭环。
- [ ] 重复点击、快速切场景、暂停/恢复、失焦、保存失败/重试、未保存退出提示。
- [ ] 三次结构化试玩或三名玩家，记录理解、完整局时长和后段决策；无真实参与者则明示限制。
- [ ] 整理资产来源/许可；测一次代表场景性能和最大普通档大小，有问题才针对性优化。

退出：P3-A–E 可评审，玩法/存档显著缺陷已回到对应包修复。回退：删减装饰，不删失败行为和提示。

## 10. W8：候选验收与本地试玩交付（P4，3–5 人日）

- [ ] 冻结候选引擎/模板/规则/内容/hash；跑相关规则、保存、输入和旧版回归。
- [ ] 首次运行已登记 V2 独立种子集，保留全量结果，不挑胜局、不把既有 V1 胜率贴上 V2 标签。
- [ ] 导出 macOS 本地包，解压并从包启动，真实输入新局/继续/战斗/结局；记录包 hash/启动说明。
- [ ] Web 实际浏览器验证加载/中文/输入/刷新恢复/文件导入导出；失败提供复现、日志和限制。
- [ ] 产出 AC1–AC10 矩阵和已知限制；README/运行说明与真实产物一致。
- [ ] 按 workflow 另行提出准确提交清单，确认后才提交；不自动上传、公证、上架。

退出：[validation.md](validation.md) 的验收矩阵有真实证据；仅声明实测平台。回退到具体失败包，不整体重写规则或删用例。

## 11. 剩余工作量与调整

| 承接任务 | 包 | 剩余人日 |
| --- | --- | --- |
| P2 Godot 基础 | W0–W3 | 7–11 |
| P3 三地点/玩法试玩 | W4–W7 | 8–13 |
| P4 集成验收 | W8 | 3–5 |

前提：一名熟悉 TS/Godot 的开发者、占位资产、只本机桌面验收、有限事件重排、无旧档转换/外部发行。最先 1–2 人日目标是 W0 原生窗口，不是完整游戏的工期承诺；之后每包展示真实增量。

旧路线全程估算 19–31 人日包含 P1；这里是 P1 之后的剩余重估，加入更明确的可见交付、恢复/对照和有限玩法实验。安装环境受阻、重大 SVG/字体重做、复杂新机制或增加平台时必须按证据重估，不承诺交付日期。

## 12. 实施治理

开工前读取当前包适用 spec，按 Trellis 实现/检查流程执行。最新计划批准后先进入 P2，不直接把该规划子任务当产品实现目标；后续阶段仍按退出门槛交接。

P1 已按后续用户指令提交，保留 in_progress 表示尚未归档，不代表正在开发 Godot。用户已明确要求 `蛊真人.txt` 一并提交，按独立提交处理；具体分组见P1 commit-plan.md。禁止全仓库reset；本次推送不构成最新架构方案的实施批准。
