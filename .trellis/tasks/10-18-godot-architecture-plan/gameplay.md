# 玩法重构方案

这里区分既有事实、已确认方向与本次推荐实验。引擎迁移本身不会自动增加策略深度，必须改变实际决策或反馈，再用完整试玩检验。

## 1. 首版核心循环

```text
看目标/机会/风险 → 去地点 → 预览成本 → 办事/修炼/探索/交往
       ↑                                     ↓
  次日调整计划 ← 日结供养/恢复/窗口变化 ← 处理事件或回合战斗
       └──────── 最终危机：战备应对 / 情报庇护 → 解释结局
```

保留独立 14 日、每日 3 行动、三地点、四蛊、两关系对象。普通移动、查看、预览不偷跑时间；有收益的行为明确收费。正式 165 日内容仍是后续项目，不能把全部原剧情压入十四日。

## 2. 旧版、V1 原型与 Godot 试玩的区别

| 方面 | 旧 Web 当前可玩 | 已实现 V1 规则 | Godot 目标/本次推荐 |
| --- | --- | --- | --- |
| 交互 | 地图/面板按钮和文字 | 无可玩 UI，CLI/测试 | 2D 小场景移动、目标交互、统一预览与 HUD |
| 日程 | 方源篇推进至 165 日 | 独立 14 日/42行动 | 保留短局，改进中后段决策节奏 |
| 成长 | 修为不进入方源狼潮评分 | 修为提升真元/攻击 | 在 UI 展示真实增益；让后段准备有用途 |
| 蛊虫 | 两蛊，终局按持有种类评分 | 四蛊的战斗/防护/侦察/成长用途，休眠/封存 | 四种用途可操作，预览供养/可用原因，防卸装逃费 |
| 关系/风险 | 关系缺实际门槛，疑心阈值难触发 | 担保/庇护、关注衰减和独立暴露 | 可见承诺链和处理手段，不堆更多全局条 |
| 危机 | 最终隐藏总分占主导 | 真实回合战或准备判定庇护 | 预警、准备清单、实际代价和原因，节奏实验后再冻结 |
| 收益 | 长期安全劳作有效 | 投资路线可达，但准备早完成 | 劳作保留恢复功能，后段有有限任务和风险机会 |
| 保存 | 旧浏览器 v2 | 原型无玩家保存 | 新独立档，待决事件/战斗可恢复 |

本次不会以“界面换成 Godot”宣称玩法已优化；V1 自动政策 100% 生还不等于人类能看懂，也不等于有挑战。

## 3. 推荐首版改造包（随本方案评审，数值待实验）

### G1：地点体现不同决策

- 学堂：修炼、守望/队长安排；显示能力门槛与所需行动。
- 客栈：收入、交付、掌柜庇护、补给和处理痕迹；显示履约条件。
- 竹林：侦察、风险事件、巡逻战斗；显示已知危险、撤退损失和未知部分。

不把安全劳作换成三个同效果名称；不要求走路消耗策略资源。没有实时敌人追逐、复杂寻路或动作判定。

### G2：中后段节奏实验

证据问题：V1 战备约第 5 日已达到主要准备，庇护约第 9 日完成安排；后续反复工作不提供足够新取舍。建议在 V2 **优先重排/改写现有 19 事件中的 3–4 个节点**，控制总内容预算；不先扩成大型任务系统。

| 时段 | 推荐改造 | 决策/代价 | 需要观察 |
| --- | --- | --- | --- |
| 1–3 日 | 保留入门与两路线入口，直接展示供养和危机目标 | 获取哪种能力、留多少钱 | 玩家能复述行动/供养机制 |
| 4–7 日 | 保留首次委托/巡逻；较早给出后期机会期限 | 投资成长还是落实人情，是否承担暴露 | 两路线都能理解并进入 |
| 8–11 日 | 重排一组限次筹备：战备演练/庇护路线落实 | 行动、真元或补给占用；不能纯钱代办 | 已有投入改变可选方案，不凭空新增必死门槛 |
| 12–14 日 | 两项预告过的可选机会：补足准备或换收益承担风险 | 额外储备、协助守望或处理遗留痕迹 | 不是每天只按 WORK；可选择保守结束当日 |
| 危机 | 延续战斗/庇护两出口，解释实际准备 | 有限补给与负担兑现 | 胜负能追溯到准备，而非突然隐藏分 |

上述事件优先使用已有 flag/relation/resource/gu/battle/crisis effects。只有无法表达必要因果才新增一种状态/效果，并补合同、保存和测试；不为“更有策略”同时加饥饿、疲劳、士气、市场波动等条。

实验不靠连续 WORK 惩罚、随机征税、偷改敌人或看玩家路线动态加难度。劳动始终是明确的小额恢复入口；已经错过必要窗口或自选致死风险可以失败，但须能解释。

### G3：投资必须兑现

- 修为改变真元容量/攻击等真实能力；界面显示当前值和下一门槛，不能只展示经验数字。
- 月光/玉皮对正面战斗有用，地听草对情报机会和准备有用，酒虫提高成长效率但产生养护负担；不要求把四蛊全拿满。
- 队长与掌柜的用途分别展示为已落实事项，关系值不自动替代实际交付。
- 封存、休眠、装备状态分开显示；今日已经形成的供养不因卸装消失。
- 关注与暴露说明来源、后果与处理代价，不能用睡觉清除一切。

### G4：回合战斗与结果反馈

先显示敌人意图和当前可知伤害，按钮同时显示真元、补给和禁用原因。攻击、防御、两战斗蛊、药草、酒、撤退继续使用规则统一结算；战斗回合不扣日程行动。不新增走位/反应速度考核。

危机前显示战备和庇护各自已落实/未落实条件与期限，不用攻略箭头替玩家选唯一动作。结局列出实际有效蛊、成长、情报、人情、损失和不足；不虚构“使用补给”或“成功转入战斗”等未发生事项。

## 4. 实验验收与停止条件

这些是设计假设，V2 冻结前可依据证据调整并记录，不能作为已经通过的数据。

| 指标 | 推荐观察目标 | 方法/限制 |
| --- | --- | --- |
| 可达性 | 两类准备路线均有合法完整成功轨迹，纯囤钱不能替代全部准备 | 固定种子、混合策略、低资源恢复与因果消融 |
| 后段选择 | 8–14 日内存在至少两次会改变准备或结果的不同选择，能选择承担或回避风险 | 同种子分支对照；“打开不同文案”不计 |
| 重复程度 | 调整后的两参考政策各自后七日 WORK 行动占比相对 V1 降低；提议至少下降 20 个百分点 | 报绝对次数/总行动及前后值；若 V1 已低则重审阈值，不靠空耗动作凑数据 |
| 可理解性 | 试玩者能说出每日行动、今晚供养、当前目标和一个失败原因 | 三次结构化独立试玩或三名玩家；无人测试明确未完成 |
| 时长 | 完整首局目标 20–35 分钟，移动/读文/战斗分别记录 | 自动模拟耗时不能充当玩家时长 |
| 鲁棒性 | 错过一个可选节点后不出现无提示软锁；已承担风险允许失败 | 窗口边界、缺钱、休眠、撤退和坏档用例 |

沿用父计划“两投资政策生还率≥70%、劳作≤40%”作为候选底线，不追求把已准备政策从 100% 强行调低。若新机制只降低胜率、没有新增可理解决策，就回退该实验。

V2 开发集建议仍用 1–100；旧 10001–10100 已看过，仅作回归。新盲测建议用 20001–20100，集合在调参前登记，候选规则冻结后首次运行，保留全部结果；若依据它调整，再指定下一独立集合，不能继续称原集合未见。

完整商队/考核玩法、动态市场、全合炼树、更多 NPC 政治、长期成长、多章节和正式第 165 日狼潮，不纳入本次首版。没有从十四日原型按比例推算长篇收益或工期。
