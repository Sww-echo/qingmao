# P4 验收设计

## 证据矩阵

建立需求 -> 测试/轨迹 -> 执行环境 -> 结果 -> 产物的映射。记录引擎/模板/规则/内容版本、种子集和包校验值；同一版本下复现，不凭旧文档测试数字认定通过。

## 分层验证

1. 规则：合法/非法操作、RNG、供养、窗口、两策略因果对照。
2. 持久化：事件/战斗/日结中断、坏档、旧档、备份。
3. 体验：真实输入闭环、风险理解、中文与布局。
4. 平衡：V2冻结后首次运行的新保留种子，另报告后段重复度与因果选择；旧V1开发/保留集只能作为历史和移植回归。
5. 导出：本机桌面实际运行；Web 浏览器实际加载与持久化。

性能预算用实际机器与场景数据制定并报告，不预先写未经测量的帧率承诺。无外部试玩者时标记可理解性验证的限制，不让模拟替代人类理解。

## 扩展决定

如果同质化策略、不可解释失败或存档风险仍在，回到对应 P1/P2/P3。首版通过只支持继续规划中期内容，不能推出 165 日已平衡。
