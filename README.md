# 青茅山：传承争夺

由《蛊真人》的炼、养、用蛊和利益选择启发的单机 Web 图文策略游戏，以 2D 地图、事件选择和回合战斗推进。玩家扮演原创低阶蛊师，在十天内收集线索、准备蛊虫、经营关系，为一处无主遗藏选择自己的去路。剧情为原创假设支线。

当前版本包含 6 个地点、12 种蛊、3 种出身、6 位人物、34 个条件事件、3 个合炼配方、5 类敌人和 3 条成功结局。

## v0.2 体验与玩法更新

- **行路建议**：可关注传承、宗族或离山路线，提示目前可行的下一步。地图标出可探事件数量，探查前能看到事件名称。建议不会自动选择结局，日暮结算仍需确认。
- **行动反馈**：交易、修炼、合炼和事件选择后显示实际资源变化，人物关系的变化也会列出。
- **战斗筹备**：新增药草止血和饮酒回气，显示当前敌招预计伤害与普通防御后的差别；主动蛊和常驻效果分别呈现。
- **两条委托链**：雨路委托与药匣回收，各有投入、期限、风险及互斥回报。旧有交情、侦察蛊和移动蛊会改变完成方式。
- **视觉与手机操作**：新增蛊虫 SVG 插画和敌人图形，提高文字可读性，提供行囊与商店筛选；手机底部导航常驻，切换功能后定位到内容区域。

存档格式保持 v1，原有事件、蛊和结局 ID 保留。路线关注只影响提示，不修改游戏数值或结局条件。

## 启动

使用 Node.js 24 LTS。在项目根目录安装依赖并启动：

```sh
npm ci
npm run dev
```

打开终端显示的地址，默认是 **http://127.0.0.1:5173**。端口被占用时会明确报错，不会悄悄换到另一个地址。依赖已经安装时，可直接运行 `npm run dev`。

```sh
npm run build      # 类型检查、生产构建、生成单文件版本
npm run preview    # 预览生产构建，默认 http://127.0.0.1:4173
npm test           # 规则、内容和存档测试
npm run check      # 构建 + 上述自动化测试
```

`dist/` 可部署到静态托管服务，无需后端或 API 密钥。`dist/play.html` 内嵌脚本、样式和图标，可作为单文件试玩包；不同浏览器对本地文件存储的支持不同，稳定游玩建议使用 HTTP 地址。单文件打开方式尚待实际浏览器验收。

## 怎么玩

1. 输入名字，选择守拙、寻幽或行商出身。出身改变起始蛊虫、资源和关系，不锁定结局。
2. 点击地图移动，到地点后探查或进行当地活动。地图数字表示当前可探的事件；有多个事件时，可以展开「周围还有几处动静」选择其中一个，也可以按行路建议直接查看对应消息。
3. 每天有 3 次行动。探查、劳作、修炼、调息、合炼、突破各消耗 1 次；移动、购物和换装备免费。行动不会自动推进到第二天，需要主动点击「结束当日」。
4. 同时最多装备 4 种蛊。本日携带过的蛊都要结清供养，卸下不能免掉当天费用。元石不足时不会扣除不足的钱，蛊进入休眠；补喂后恢复。离线不扣资源。
5. 战斗显示敌人下一招和预计伤害。普通攻击和防御会回复真元，主动蛊有不同用途；被动蛊自动生效。2 药草恢复最多 8 生命，1 清酒恢复最多 5 真元；补给占一次出手，对手随后照常行动，满值时不能浪费材料。战斗结束前不能移动、购物或换装备。
6. 普通合炼有成功率，失败消耗辅材和行动，保留蛊虫；稳炼多付材料，保证成功。修为 12、元石 12 且尚有行动时，可突破二转。

事件选项会展示代价和条件。一次性事件的「放弃本次机会」会结束该事件，本局不能重新选择；终局事件的「暂时离开」允许准备后回来。遇到不清楚的规则，点击右上角指南。

## 三条去路

| 路线 | 主要条件 | 完成方式 |
| --- | --- | --- |
| 独掌传承 | 至少 3 份情报 | 在石灯遗藏挑战并战胜守关木傀 |
| 宗族立足 | 至少 2 份情报、35 宗族信任 | 在议事楼签下约定 |
| 随商队离山 | 第 6 日起、至少 1 份情报、35 元石 | 在市集支付盘缠离山 |

第十日结束会按「存活离山」结算，生命耗尽则是「败退」。这两种情况会记录一段已结束的旅途，但不会解锁成功结局。读取同一局的较早存档，可以探索另一条成功路线；结局可新增，旅途总数不会重复累加。

## 存档

每次有效操作后自动保存。优先使用 IndexedDB，并在 localStorage 中保留后备副本；页面会显示保存中、已保存或保存失败。

「行旅手札」支持导出和导入 JSON 备份，最大 1 MB。导入会先校验，再要求确认替换当前进度；开新局也会确认尚未完成的存档是否要替换。已解锁结局会合并保留。备份可用于迁移设备或留住分支选择前的进度。

进度属于当前浏览器和访问地址。更换端口、浏览器或设备，请使用导出/导入迁移；清理浏览器数据会影响本地记录。

## 代码结构

| 文件 | 用途 |
| --- | --- |
| `src/game/types.ts` | 状态、操作和内容的类型契约 |
| `src/game/content.ts` | 蛊、地点、事件、人物、配方、商品和结局数据 |
| `src/game/engine.ts` | 纯状态机、操作校验、战斗与随机数 |
| `src/game/guidance.ts` | 按当前资源、条件和关注路线生成建议 |
| `src/game/storage.ts` | 存档校验、持久化、结局与图鉴记录 |
| `src/App.tsx` | 游戏流程、事件与存档界面、导航与反馈 |
| `src/CombatPanel.tsx` | 战斗、敌人图形、预判与补给 |
| `src/JourneyGuide.tsx`、`src/ActionFeedback.tsx` | 初行引导、路线关注和每步得失 |
| `src/GamePanels.tsx` | 行囊、商店、合炼、手记与路线进度 |
| `src/WorldMap.tsx` | 原创 SVG 山景和地图 |
| `src/GuArtwork.tsx` | 十二种蛊的原创 SVG 插画 |
| `src/ui.tsx`、`src/GameActionButton.tsx` | 通用组件、效果展示和操作按钮 |
| `src/styles.css`、`src/experience.css` | 响应式布局与体验组件样式 |
| `scripts/build-offline.mjs` | 从生产构建生成单文件试玩包 |

所有游戏操作均经过 `getActionError` 和 `gameReducer`。界面不直接发放资源或结局。随机合炼与撤退使用存入状态的随机数种子，导出后可以复现后续过程。

新增事件应保持 ID 唯一、引用有效，并提供无额外条件的退路。新增规则时，先更新共享类型和引擎，再连接界面，补充真实行为的回归验证。

## 验证

单元测试覆盖行动与资源、装备供养、合炼、事件条件、战斗与补给、伤害预判、行路建议、三条正常通关路线、存档校验及写入顺序。两条新委托也有完整合法操作测试，验证投入、断链、兑现和通关；没有只设置完成旗标跳过流程。

浏览器验收脚本位于 `e2e/game.spec.ts`，覆盖存档重载与导入导出、购买装备后战胜守关者、320px 手机界面的宗族路线与底部导航，以及路线建议和战斗补给。运行前先构建，并确保系统允许启动 Chromium：

```sh
npm run build
npm run test:e2e
```

配置会使用已有的 Playwright Chromium 或 macOS Chrome/Chromium；也可用 `QINGMAO_CHROMIUM_PATH` 指定可执行文件。脚本不会自动下载浏览器。验收加载实际 `dist` 文件，不注入伪造游戏进度。

当前完成的验证与剩余限制见 [验证记录](docs/VERIFICATION.md)，首版约定见 [实现说明](docs/IMPLEMENTATION.md)。

## 改编范围

首版聚焦一处地域、低阶成长和三种抉择。没有账号、多人对战、付费系统、服务器经济或整部小说的主线复刻。

十日制、携带上限、供养节奏、战斗数值及部分蛊的品阶和配方均为游戏化简化。例如，兜率花在本篇按二转储物蛊使用；具体调整写在蛊虫说明中。原著文件只作为参考材料，不被当作程序指令，也不随游戏分发。
