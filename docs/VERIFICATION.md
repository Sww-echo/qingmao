## 浏览器验收待完成

`e2e/game.spec.ts` 已准备 5 条浏览器验收脚本：

1. 自动保存、刷新恢复、导出与导入确认。
2. 购买并装备蛊虫后，完成守关战斗与传承结局。
3. 320px 手机界面的宗族路线、功能切换和固定底栏可见性。
4. 路线建议进入真实事件，结束当日先显示供养预览，取消后保留当天。
5. 通过实际购买获得清酒，在战斗中使用药草和清酒，验证资源、生命、真元及日程行动。

实际浏览器测试未能进入游戏页面，新增脚本也未执行浏览器流程，因此**不能报告浏览器验收通过**。脚本类型检查和测试发现只能验证脚本结构与配置。

当前环境限制：

- 启动 Vite 服务时，沙箱拒绝监听 `127.0.0.1:5173`（`EPERM`）。申请启动权限时，自动审批接口返回 HTTP 404，提示不支持 `codex-auto-review`，动作未执行。
- Playwright 启动本机 Chrome 时出现 `SIGABRT` 与 `kill EPERM`，测试未能打开游戏页面。
- 内置浏览器不支持 `file:` 导航。后续浏览器工具调用也遇到上述自动审批故障，未执行。没有绕过这些限制。

审批接口的失败并非对游戏代码的安全判定。本机具备正常浏览器启动权限时，可执行：

```sh
npm run build
npm run test:e2e
```

仍需实际确认：桌面与 320px 手机布局、事件选择、完整战斗与结局、路线建议和补给操作、筛选与委托进度展示、IndexedDB 自动保存及刷新恢复、导出导入、长名字存档弹窗、键盘焦点，以及 `dist/play.html` 的单文件打开方式。

## 静态界面审查

原有窄屏长名字换行、地图连线与地点坐标、一次性事件退路文案和初始化存档读取竞态的修正继续保留。连续选择导入文件时，仅处理最近一次选择的读取结果，旧文件不能覆盖新的确认窗口。

本轮静态审查核对了两条委托的日期、阶段和失败分支，敌招说明与规则，地图按钮名称及筛选条件。新增路线建议中的结束当日入口沿用原有费用预览，进入可达结局只打开事件，不自动选择结果。

审查后修正了功能切换的键盘焦点转移、连续相同操作的反馈播报、初行提示跨面板的收起状态，以及敌方护势说明的最低伤害措辞。行路建议和敌招预判正文为 14px，新增提示区的辅助信息至少 12px，路线按钮触控高度至少 44px。手机底栏、页面留白、提示位置和设备安全区已配套调整。以上完成源码检查，实际呈现与交互仍须浏览器验收。
