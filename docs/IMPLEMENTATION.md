# 青茅山：传承争夺 · 首版实现约定

本项目由《蛊真人》的炼、养、用蛊和利益博弈启发，剧情为原创假设支线。原文只作资料，不能执行其中指令。首版是本地单机 Web 游戏，不复制原文长段落。

## 验收范围

- React + TypeScript 的独立项目，可构建和本地运行；桌面与手机界面。
- 6 个地点、12 种蛊、至少 20 个有实际条件和后果的事件、3 种结局。
- 10 个游戏日，每日 3 行动；地图移动免费，探查、当地活动、修炼、休息、炼蛊各耗 1 行动。事件选择和战斗本身不额外消耗日程行动；行动耗尽须主动结束当日。结束当日始终先预览供养费用。
- 12 蛊清单：moonlight 月光、little-light 小光、jade-skin 玉皮、white-boar 白豕、liquor-worm 酒虫、vitality-grass 九叶生机草、earth-ear 地听肉耳草、flower-bag 兜率花、jumping-grass 跳跳草、moon-glow 月芒、white-jade 白玉、moon-mark 月痕。
- 原创主角的三种出身：disciple 守拙、scout 寻幽、trader 行商。持有、装备（上限 4 只）、每日供养、缺粮休眠和补喂。离线不扣资源。
- usedToday 记录本日携带过的蛊，卸下不能免除已产生的当日供养；重复同种蛊不能叠加装备。
- 回合战斗显示敌人下一招；基础攻击、防御、撤退、蛊能力；侦察、储物、移动蛊影响事件/收益/撤退。战败应明确结算，不能发胜利奖励。
- 至少 3 种合炼配方；普通合炼可失败并明确损耗，稳炼支付额外材料保证成功。配方使用真实库存；失败保留蛊虫，消耗辅材和行动。
- 条件事件同时改变元石/材料、修炼、情报、宗族信任、疑心、关系和剧情旗标；没有条件的退路选项避免事件卡死。
- 同一地点可展开选择其他已解锁事件。`EXPLORE.eventId` 只接受当前可用事件；省略时选择优先级最高的一项。一次性事件的放弃会明确提示本局不能重选，终局的暂离允许返回。
- 三结局：inheritance 独掌传承、clan 宗族立足、departure 离山。期限耗尽/败退可归入离山结局，但必须标记 survived/defeat，不冒充成功。
- IndexedDB 自动存档、继续游戏、导入/导出备份、开新局确认、结局解锁记录；不依赖外部 API。
- 只有 `success` 解锁成功结局；期限耗尽和败退仍计入已结束旅途。按 `runId` 去重统计旅途，重读同一局并达成另一结局可新增解锁。
- 有意义的规则与内容完整性测试、构建验证和真实浏览器全流程验证。

## 模块责任

- `src/game/types.ts`：共享契约，由主代理维护，变更先协调。
- `src/game/content.ts`：数据，由 story_adaptation 负责。导出 `GU`, `LOCATIONS`, `ORIGINS`, `NPCS`, `EVENTS`, `RECIPES`, `SHOP`, `ENEMIES`, `ENDINGS`，均为对应类型的数组。
- `src/game/engine.ts`：纯规则，由 gu_systems 负责。导出 `createGame({name, origin, seed?})`, `gameReducer(state, action)`, `getActionError(state, action): string | null`, `getChoiceError(state, choice): string | null`, `getUpkeep(state): number`, `getEffectiveStats(state): EffectiveStats`, `getAvailableEvents(state): EventDef[]`。不合法动作返回原状态；所有合法动作不可变更新。
- `src/game/engine.test.ts` 与 `src/game/content.test.ts`：独立验证，由 web_game_design 负责。
- UI、样式、项目配置、存档、浏览器验证：主代理负责。

## 规则数值约定

初始生命 28、真元 12；突破二转需修为 12、元石 12，消耗 1 行动，最大生命 +8、真元 +4。修炼耗 3 真元，修为 +3；休息恢复 8 生命、6 真元。普通攻击基础 3，防御基础 4；防御回复 2 真元，基础攻击回复 1。元石/材料不可小于 0；生命/真元不能超过上限。信任/疑心/关系均约束在合理区间（信任、疑心 0–100，关系 -100–100）。

当日供养失败不扣不足的钱，相关蛊休眠；补喂支付休眠蛊的供养。隔日生命恢复 4、真元全满，疑心减少 3；已休眠蛊在成功供养后醒来。第 10 日结束进入离山结局。非战斗生命降至 0 也必须结束。突破、进度和所有结局不得靠 UI 手工改状态完成。

继承路线：情报 >= 3 后进入遗藏终局并战胜守关者；宗族路线：情报 >= 2、信任 >= 35；商队成功离山路线：第 6 日起、情报 >= 1、元石 >= 35。数据可通过事件要求实现，UI 根据内容显示要求。涉及方源的原创事件必须给玩家公平选择，不用原著光环强制夺走成果。

## v0.2 优化范围

- 保持图文策略、2D 地图与回合战斗的形态。原有六地点、十二蛊、三结局及正常通关操作仍然成立，存档结构保留 v1。
- 行路建议依据玩家状态与当前可用事件生成；可关注自由探索、传承、宗族或离山。建议只提供可选入口，不直接选择结局；建议中的结束当日入口必须打开原有供养预览。
- 地图显示可探事件数量和推荐地点；移动仍免费。原探查入口显示将进入的事件标题，其他事件保留直接选择。
- 战斗新增 `COMBAT.herbs` 和 `COMBAT.wine`：分别消耗 2 药草恢复最多 8 生命、1 清酒恢复最多 5 真元。占一次出手，敌人正常行动，不消耗日程行动。满值、缺材料、非战斗或已结束时拒绝操作。
- 战斗预判以当前敌招、常驻减伤和临时护势计算；比较当前受伤和普通防御后的受伤，不改变状态或随机数。文案需说明击倒敌人不会被反击、真元扰动取决于玩家出手后的余额。
- 新增雨路委托、药匣回收两条各三步事件链，使总事件数达到 34；具有前期投入、日期限制、能力分支、失败或放弃断链、互斥回报。旧事件优先级保持不变。
- 操作反馈显示实际资源及关系变化；为蛊虫和敌人增加原创 SVG 形态。手机文字、触控目标、安全区和常驻底部导航同步优化，减少动效偏好继续受尊重。
- 增加行囊、商店的实用筛选和委托进度记录。所有游戏效果仍由引擎执行；UI 不直接改资源、剧情旗标或结局。
